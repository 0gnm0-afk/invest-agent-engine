# Collaboration contract `collaboration.v1`

Backend contract for the published MCP connector. The production database/backend is not bundled.

## Transport and authority

`AnalysisService.dispatch(op, arguments, origin, principal=...)` is the in-process adapter. The principal is supplied by trusted server authentication, never by arguments. Values: `collaboration`, `risk`, `browser`, `legacy`. HTTP `/api/analysis-rpc` resolves dedicated capability tokens for collaboration/risk; `/health` never exposes them. MCP defaults to collaboration; a separately configured process with `INVEST_ANALYSIS_ROLE=risk` uses the risk capability. Same-OS processes with access to credential files are not isolated security principals. No claim of human identity beyond explicit local UI confirmation is made.

All common writes require `contract_version: collaboration.v1`, `analysis_key`, `snapshot_id`, `expected_revision` (integer, initial 0). The revision is per analysis case, across all common record kinds. Conflict => HTTP409, reread and reconcile, never overwrite/retry blindly. All records are append-only `analysis_items`; legacy reports are readable, never active plans. Client `author`, `area`, `confirmed_by_user`, `status`, versions or IDs cannot elevate authority.

## Operations / MCP names

* `collaboration_read` / `analysis_collaboration_read(analysis_key)`: read-only; no capture, refresh or implicit migration. Returns contract_version, analysis_key, stock_key, revision, current, plans, active_plans, records, legacy_records, snapshots, related_cases, links. `current` is latest collaboration discussion with original record ID; risk notes never replace it. `plans` contains latest draft per plan_id, `active_plans` exact adopted versions even if newer drafts exist. All history remains in records. Empty current is null.
* `discussion_save` / `analysis_save_discussion`: common write envelope plus `title`, `body`, `sections`, `open_questions`, `references`. Collaboration only. Sections is a partial map of `identity_basis`, `business_evidence`, `judgment_invalidation`, `purpose_plan`, `responses`, `scenario_assumptions`, `discussion_history`, values text or null. It is a complete current summary, not an implicit merge; supplied source records remain linked. Missing fields normalize to null. No seven-question form.
* `discussion_note_save`: browser only; common envelope plus body. Appends available user text without replacing the agent's current summary; next reader sees the new utterance in records. No plan activation.
* `plan_save` / `analysis_save_plan`: envelope plus `plan_id` (null creates), `expected_plan_version` (0 creates), `plan`, `references`. Collaboration only. A new immutable plan_version is assigned server-side, previous_record_id retained. Plan fields and nullable semantics are demonstrated in `examples/collaboration-v1.json`. `conditions` and `scenarios` may be empty. Unknown enums/fields, wrong currency, negative quantities, invalid fractions, duplicate IDs/priority are rejected. Semantically incomplete values remain null and produce blockers, not defaults.
* `risk_review_save` / `analysis_save_risk_review`: envelope plus `title`, `body`, `plan_record_ids`, `calculation` (null or object with `code_version`, `input_snapshot_ids`, `assumptions`, `result`), `references`. Risk only. Plan IDs must belong to this case; calculation snapshots must exist in this case. Does not mutate plans, current summary or adoption. B may store partial calculation results with explicit limitations in result.
* `plan_review` and `plan_decide`: browser only, not MCP. Review accepts analysis_key, plan_record_id, expected_revision; returns exact version/hash, revision and a short-lived single-use confirmation. Decide envelope (no snapshot_id) plus confirmation, action (`adopt` / `revoke`), reason. Confirmation binds record/version/hash/revision and browser session. Atomic compare/append. This adopts an exact local plan only, never execution, order permission, chart adoption or risk policy. Incomplete adopted plans stay blocked for unsupported calculations. New draft does not replace adopted version.
* `plan_input` / `analysis_plan_input`: read-only, arguments analysis_key, plan_record_id, mode (`adopted` / `hypothetical`), optional evaluation_at YYYY-MM-DD. Returns plan record/id/version/hash, frozen snapshot/hash, adoption record or null, blockers, drawing evaluations, `calculation_code_version_required: true`. Adopted mode rejects inactive versions. No automatic selection of latest report or price. B must pin its own code version, evaluation horizon, account/market snapshot, FX/cost/path assumptions and use current authorized stored holdings rather than narrative quantities.

Each write returns `{contract_version, revision, record, verified: true, links}` after committed DB reread and Markdown hash verification. Failures never return success. DB is canonical; Markdown is generated before transaction commit, immutable and hash-linked; a crash before commit can leave an unreferenced file, never an active record. Re-reads detect missing/corrupt Markdown. No independently edited current.md.

## Plan meaning

`plan` has title, purpose, account_alias, allocation, conditions, scenarios. `allocation` = {quantity: decimal-string|null, basis: `initial`|`current_remaining`|`units`|null}. It is a plan allocation, not observed holdings. Each condition has id, kind (`price`|`qualitative`), statement, action (`buy`|`add`|`reduce`|`hold`|`review`), evaluation (`intraday`|`daily_close`|`weekly_close`|null), operator (`lt`|`lte`|`gt`|`gte`|null), price (decimal-string|null), currency (`KRW`|`USD`|null), quantity {value: decimal-string|null,basis: `initial_fraction`|`remaining_fraction`|`units`|null}, priority (positive integer|null), execution_price (decimal-string|null), drawing_ref (null or {drawing_id, workspace_revision, timeframe, price_basis, geometry_version, line: `line`|`other_line`}). A drawing reference always binds to this record's snapshot. Exact coordinates/hash/basis remain in the snapshot. Sloped geometry is evaluated using existing analysis_geometry at requested time; no constant-price substitution. New chart revision does not change the plan.

Scenario fields: id, evaluation_at (ISO date|null), assumed_price, currency, response (`none`|`plan`|null), price_path (null or list of {at,price}), fx_to_base, fx_as_of, cost (nullable decimal strings/date). Shared account assumptions may be completed by B in a separately pinned calculation; never silently written into the original plan.

Quantity meaning: allocation.quantity is always shares in this explicitly discussed allocation, and its basis says whether that share count was initially allocated or the stated remainder; it is never a live account balance. `units` is a stated share count without lifecycle attribution. Condition `initial_fraction` refers to this initially allocated quantity; `remaining_fraction` refers to remaining allocation after preceding modeled responses; B must reject inconsistent/unknown allocation bases. Scenario cost is the total scenario cost in scenario.currency, applied once, not per-share or per-fill. Missing is null, never zero. Scenario price_path uses ordered date observations, not validated intraday ticks or proof that a weekly-close condition occurred; B must preserve unsupported evaluation timing as blocked. `assumptions.external_inputs` in risk calculations carries immutable external account/market/FX IDs, hashes, as_of and source, since input_snapshot_ids are this case's analysis snapshots. Calculation result should carry explicit scope and limitations.

One active version per plan_id: adopting a newer version replaces the prior active version, preserving both immutable decisions. A new draft does not change adoption. Revoke requires the currently active exact record; revoking an older version cannot deactivate the newer one. Across distinct plan_ids/cases, the consumer must detect overlapping allocated holdings. Same record cannot be adopted twice without an intervening revoke.

References: list of {kind: `utterance`|`record`|`source`|`session`, reference: string|null, text: string|null, speaker: `user`|`llm`|`source`}. Utterances require accessible text; record reference must resolve in the same case. A session URL alone is not the transcript. User utterances submitted by MCP are agent-attributed statements, not authenticated user adoption. Every record stores server principal, area, identity extracted from snapshot, snapshot hash/as-of, preceding record and case revision. Stable identity missing => null + blocker, never ticker-reuse equivalence.
