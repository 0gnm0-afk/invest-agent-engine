# invest-agent-engine

개인 투자자의 **매매일지 기록·복기**, **문헌(책) 기반 방법론 노트 축적**, **다관점 종목 분석**을
위한 모델 비종속 AI 에이전트 엔진.

이 repo의 본체는 코드가 아니라 **구조**다 — 스키마, 템플릿, 파이프라인 규약.
Claude Code, Codex CLI 등 어떤 CLI 에이전트를 붙여도 같은 방식으로 굴러가도록,
모든 자산을 마크다운 + YAML frontmatter로 고정했다.

> ⚠️ 이 저장소의 어떤 출력도 투자 자문이 아니다. 에이전트 출력은 판단 보조 자료이며
> 최종 판단과 책임은 사용자 본인에게 있다. `examples/`의 데이터는 전부 합성(가상)이다.

## 핵심 아이디어

1. **자산은 하네스가 아니라 vault다** — 가치가 쌓이는 것은 방법론 노트·매매일지·분석
   아카이브. 오케스트레이션 도구는 교체 가능한 소모품으로 취급한다.
2. **방법론은 코드가 아니라 데이터** — 거장의 방법론을 "페르소나 프롬프트"가 아니라
   체크리스트·판정 기준·금지 조건으로 구조화한 마크다운 노트로 관리한다. 노트 추가 = 렌즈 추가.
3. **진입 기록은 불변** — 매매일지의 진입 당시 기록(논지·시나리오·감정)은 수정 금지.
   결과·복기는 별도 섹션에 추가만 한다. 사후 합리화를 구조적으로 차단.
4. **독서 소화 파이프라인** — 책을 읽고 발췌를 올리면 AI가 주장 단위로 추출하고
   (귀속 태그: 직접 인용/재서술/저자 해설/AI 해석), 사용자 검수를 통과한 것만 방법론
   노트에 반영된다. AI는 canonical 노트를 직접 덮어쓰지 않는다.
5. **공개 엔진 / 비공개 인스턴스 분리** — 이 repo는 엔진(구조)만. 실제 일지·포지션·
   방법론 노트 내용은 별도 비공개 vault에. `.gitignore`가 아니라 repo 물리 분리로 차단.

## 구조

```
invest-agent-engine/
├── README.md
├── ARCHITECTURE.md      ← 설계 문서 (3계층, 파이프라인, 렌즈 시스템, 로드맵)
├── schema/
│   └── 규칙_스키마.md    ← 표기 규칙, YAML frontmatter 스키마, 공개/비공개 분류표
├── templates/
│   ├── 매매일지.md            ← 진입 기록(불변) + 사후 기록 분리
│   ├── 일지_인터뷰질문표.md    ← AI가 큐를 받아 인터뷰하는 질문 순서
│   ├── 방법론노트.md          ← 체크리스트·금지 조건 구조의 렌즈 노트
│   ├── 독서_발췌.md           ← 페이지 참조를 보존하는 발췌·메모
│   ├── 독서_추출.md           ← 주장 단위 분해 + 귀속 태그 + 함정 검사
│   └── 독서_검수대기.md        ← 노트 반영 전 diff + 확인 질문
└── examples/
    ├── TEST-00_발췌.md        ← 합성 문헌으로 파이프라인 전 과정 리허설
    ├── TEST-00_추출.md        ← 귀속 태그·시점성/일화 필터 동작 예시
    └── TEST-00_검수대기.md     ← 승인/기각 흐름 예시
```

데이터 어댑터 코드(공시·시세 `DataProvider`)는 로드맵 2단계에서 이 repo에 추가된다.
원칙은 미리 고정: **조회 전용 — 주문(매매 실행) API는 설계상 사용하지 않는다.**

## 파이프라인

### 매매일지

```
사용자 큐 ("삼성전자 7만원에 100주 샀어")
  → AI 인터뷰 (질문표 순서로 빠진 것만: 논지 / 무효화 조건 / 시나리오 / 확신도·감정)
  → 정리본 확인 → 저장 (진입 기록 불변)
  → 결과가 나오면 /복기: 진입 기록과 대조, 사후 기록 추가만
```

핵심 설계: **논지 무효화 조건**(가격이 아니라 사실 기준)을 진입 시점에 강제로 묻는다.
이게 없으면 하락이 "논지가 깨진 신호"인지 "그냥 무서운 가격"인지 구분할 수 없어
감정이 결정권을 갖는다.

### 독서 → 방법론 노트

```
책 읽기 → 발췌·메모 (페이지 참조 보존, 95_문헌/발췌/)
  → 추출: 주장 단위 분해 + 귀속 태그 + 라우팅 제안 + 기존 노트와 중복·충돌 검사
  → 검수대기: 변경 diff + 확인 질문 (canonical 노트 수정 금지)
  → 사용자 승인 → 승인분만 병합 + 반영기록
```

노트 상태 관문: `draft`(정리 중) → `shadow`(참고 의견으로만 표시) → `active`(출처·
체크리스트·적용 범위·반례 완비). shadow 렌즈의 의견은 과신하지 않는다.

## 면책

- 투자 자문이 아니다. 단정적 매수/매도 지시 문구를 출력하지 않는 것이 시스템 규칙이다.
