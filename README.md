# Investment Agent Engine

투자 방법론을 정리하고 매매일지를 남겨도, 실제 종목을 볼 때 매번 같은 기준으로 후보를 찾고 보유 위험을 확인하기는 어려웠습니다. 이 프로젝트는 **공부한 기준을 반복 가능한 검토 절차로 옮기기 위해** 시작했습니다.

한국·미국 주식의 검토 후보를 추리고, 차트 구조와 섹터 흐름을 함께 보여주는 Python 투자 보조 도구입니다. 보유종목에 대해서는 사용자가 채택한 보호선까지의 위험액과 계좌 비중을 계산합니다.

> 계산 가능한 조건은 코드로 확인하고, 근거의 해석·보호선 채택·최종 매매 판단은 사용자가 합니다. 주문은 전송하지 않습니다.

현재 공개 버전은 **v2.1.0**입니다. 실제 시세·계좌 없이도 새 시장 검토 흐름을 살펴볼 수 있도록 합성 자료 데모를 제공합니다.

## 기록에서 실행 가능한 검토 흐름까지

| 단계 | 새로 연결한 부분 | 아직 사용자에게 남아 있는 판단 |
|---|---|---|
| 2026년 7월 · 초기 공개 | 방법론, 독서 내용, 매매 기록을 위한 스키마·템플릿 | 기록을 실제 종목에 어떻게 적용할지 |
| v2.0.0 · 실행형 MVP | 거래소·유동성·차트 구조로 후보를 찾고, 로컬 계좌의 보유 비중·보호선 위험을 계산 | 후보의 매력도, 보호선 채택, 매매 결정 |
| v2.1.0 · 시장 검토 확장 | 기존 후보를 보존하면서 섹터 맥락, 우선 검토 순서, 차트와 선정 이유를 연결 | 제시된 근거의 해석과 최종 행동 |

v2.0.0에서는 “어떤 종목이 조건을 통과했는가”와 “현재 보유 위험이 얼마인가”를 계산할 수 있게 됐습니다. v2.1.0에서는 그 사이에 있던 질문을 다룹니다. **후보가 여러 개라면 무엇을 먼저 보고, 해당 종목의 섹터는 어떤 상태이며, 왜 그 순서로 검토해야 하는가?**

이 확장은 새 기능을 하나의 매수 점수로 묶는 방식이 아닙니다. 원래 후보 판정, 섹터 관찰, 우선 검토 순서와 사용자의 판단을 각각 구분합니다.

## 한 번에 따라가 볼 수 있는 사례

공개 데모는 가상 한국·미국 종목 10개와 합성 시세·섹터·벤치마크를 만듭니다. 최신 가격 봉이 잘못된 2개는 이유를 기록하고 계산에서 제외합니다. 유효한 8개에서 후보 8개와 섹터 관찰 4개를 만든 뒤, 시장별 2개씩 우선 검토해 차트 4개를 생성합니다.

```text
합성 종목·시세·분류
→ 입력 품질 확인
→ 시장·유동성·차트 구조 판정
→ 섹터 관찰과 후보별 맥락
→ 우선 검토 순서·차트·선정 이유
→ 사용자의 검토와 판단

로컬 보유계좌 → 보유종목 전수 점검 → 채택 보호선 기준 위험 계산
```

데모 보고서의 `state: partial`은 결과 생성 실패가 아니라 **입력 2개를 제외한 사실을 표시한 상태**입니다. 섹터 분류가 없는 종목도 후보에서 삭제하지 않고 섹터 맥락만 결측으로 남깁니다. 결과가 완성돼 보이더라도 어떤 자료를 사용하지 못했는지 확인할 수 있어야 한다고 판단했습니다.

위 종목 수와 차트 수는 데모용 합성 자료에서 얻는 결과입니다. 실제 시장 후보의 품질이나 투자 성과를 뜻하지 않습니다.

## 설계에서 중요하게 본 네 가지

### 1. 잘못된 입력을 그럴듯한 근거로 바꾸지 않기

v2.1.0의 시장 검토 경로는 가격·거래량·거래 세션·완료봉 여부를 먼저 검사합니다. 시계열이 잘못되면 임의로 채우지 않고 해당 종목의 계산을 제외하되, 원래 입력과 제외 이유를 남깁니다. 섹터 지표도 **지표별 사용 종목과 제외 종목**을 기록해 어떤 자료로 계산했는지 확인할 수 있게 했습니다.

벤치마크나 섹터 분류가 없으면 해당 상대강도·맥락을 결측으로 표시합니다. 분류가 빠졌다는 이유만으로 차트 구조 후보를 탈락시키지는 않습니다.

### 2. 후보 발굴과 우선 검토를 구분하기

기존 스크리너는 거래소·유동성·미국 시가총액 조건을 적용하고, 63·126·252세션 창의 차트 구조(S1–S4)를 계산합니다. 이동평균은 후보의 현재 위치를 설명하는 데 사용합니다.

v2.1.0은 여기에 섹터의 63·126세션 수익률, 벤치마크 대비 상대강도, 추세, SMA60 위 종목 비율과 거래량 활동을 덧붙입니다. 이어 최근 차트 단계, 장기 이동평균과의 거리, 저항·지지 상태, 섹터 맥락 등을 **정해진 순서대로 비교**해 먼저 볼 후보를 정합니다. 서로 다른 근거를 가중 합산한 매수 점수는 만들지 않습니다.

시장별 검토 수를 제한해도 전체 후보와 원래 판정은 그대로 남습니다. 우선 목록에 들어간 이유와 이번에는 선택되지 않은 이유를 각각 표시합니다.

### 3. 차트와 보유 위험을 검토 가능한 형태로 보여주기

우선 검토 종목의 차트는 현재 자료로 선택한 추세선을 **앵커가 확정된 시점부터 첫 가격 침범까지** 표시합니다. 과거의 어느 날에도 같은 선을 선택할 수 있었다는 뜻의 백테스트로 제시하지 않습니다.

로컬 계좌 기능은 신규 후보 조건과 관계없이 이미 보유한 종목을 점검합니다. 현금성 자산을 분리하고, 보유 비중·사용자가 채택한 보호선까지의 위험액·ATR 접근 경고·계좌 합산 위험을 계산합니다. 보호선이 없으면 위험을 0으로 만들지 않고 계산할 기준이 없음을 남깁니다. 계획·분할·미체결 대조, 로컬 원장, 실행 상태 저장과 백업·복원도 포함합니다.

### 4. 코드와 사람의 책임을 분리하기

현재 공개 시장 검토 데모는 **LLM을 호출하지 않습니다.** 재현 가능한 조건 확인과 수치 계산은 Python이 맡고, 후보와 보유종목을 어떻게 해석할지, 보호선을 어디에 둘지, 실제로 매매할지는 사용자가 결정합니다. 공개 코드에 없는 기업 조사나 비정형 근거 해석을 완성 기능으로 소개하지 않습니다.

## 합성 시장 검토 데모 실행

Python 3.12 이상이 필요합니다. 저장소 루트에서 가상환경을 만듭니다.

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv/Scripts/python.exe -m pip install -e .
.venv/Scripts/python.exe examples/market_review_demo.py --output ../synthetic-market-review
```

macOS / Linux:

```sh
.venv/bin/python -m pip install -e .
.venv/bin/python examples/market_review_demo.py --output ../synthetic-market-review
```

실행 후 `../synthetic-market-review/report.html`을 브라우저에서 엽니다. 설치에는 패키지 다운로드가 필요할 수 있지만, **설치 후 데모 실행에는 네트워크·API 키·계좌·LLM이 필요하지 않습니다.** 출력은 저장소 밖의 새 폴더에 만들며 기존 폴더를 덮어쓰지 않습니다.

| 결과 파일 | 확인할 내용 |
|---|---|
| `report.html` | 섹터 관찰과 우선 검토 목록 |
| `charts/` | 선정 종목의 차트 이미지·HTML·계산 근거 |
| `screen.json` | 전체 종목의 원래 후보 판정과 순서 |
| `sectors.json` | 섹터 지표와 지표별 사용·제외 종목 |
| `context.json` | 후보를 유지한 섹터 맥락 |
| `priority.json` | 전체 후보의 검토 순서와 선택·미선택 이유 |
| `quality.json` | 자료 제외 사유 |

`--limit-per-market 3`처럼 시장별 우선 검토 수를 바꿀 수 있습니다. 이 설정은 먼저 볼 목록과 차트 수만 바꾸며 전체 후보 판정을 바꾸지 않습니다. 수식·전체 산출물·데모 입력 범위는 [합성 시장 검토 안내](docs/SYNTHETIC_MARKET_REVIEW.md)에 정리했습니다.

기존 v2.0.0 계좌 경로도 별도로 실행할 수 있습니다. 합성 시세·합성 계좌로 리포트를 생성하려면 설치한 가상환경의 Python을 사용합니다.

```powershell
# Windows PowerShell
.venv/Scripts/python.exe examples/demo.py --instance ../invest-agent-demo
```

```sh
# macOS / Linux
.venv/bin/python examples/demo.py --instance ../invest-agent-demo
```

결과는 생성된 `reports/`에서 확인합니다. 이 데모의 `partial`은 가치평가 전망치 등 일부 입력이 없다는 뜻으로, 시장 검토 데모에서 잘못된 봉을 제외한 상태와 원인이 다릅니다. 계좌 입력 계약은 [TRADING.md](TRADING.md)에 있습니다.

## 공개 범위와 검증

시장 검토 데모의 회사·가격·거래량·섹터·벤치마크는 모두 **합성 자료**입니다. 380개 가상 평일을 사용하며 마지막 세션은 `2025-06-13`입니다. 실행 당일 시세와 실제 거래소 휴일을 반영하지 않습니다. 비공개 워크벤치의 실제 수집·분류 검증, 인증정보, 계좌와 사용자 판단 기록은 공개하지 않았습니다.

기존 [공개 공급자 연결 설정](examples/screen_exchange_review.json)은 거래소별 최대 100개를 요청하는 연결 점검용이며, 위 합성 데모와 별개입니다. 공개본의 전체 시장 전수 실행·매일 자동 운영 또는 투자 성과를 검증했다는 의미는 아닙니다.

합성 자료와 모의 공급자 테스트는 계산 결과, 원입력·전체 후보 보존, 결측·오류 격리, 추세선 확인시점, 네트워크 차단 상태의 종단 실행, 기존 출력 폴더 보호를 확인합니다. 설치한 가상환경에서 실행할 수 있습니다.

```sh
python -m unittest discover -s tests -p test_market_review.py -v
python -m unittest discover -s tests -v
python -B scripts/check_git_publication.py --repo .
```

이 검증은 실계좌 연결·실주문·투자 판단 개선의 증거는 아닙니다. 실제 계좌 입력과 생성 리포트는 저장소 밖의 비공개 폴더에 둡니다. 공개 파일과 이력의 검사 범위는 [PUBLICATION.md](PUBLICATION.md)에 기록했습니다.

앞으로는 실제 운영 입력의 기준시점·단위·결측을 더 안정적으로 검증하고, 후보 선정 근거와 사후 검토 기록이 판단에 도움이 되는지 확인하려 합니다. 아직 검토 시간 절감이나 투자 수익 개선을 측정한 결과로 제시하지 않습니다.
