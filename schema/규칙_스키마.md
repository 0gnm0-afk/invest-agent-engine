# 규칙과 스키마

## 1. 표기 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 날짜 | `YYYY-MM-DD` | 2026-07-12 |
| 시각 | `YYYY-MM-DD HH:MM` (KST 기본, 타 시간대는 명기) | 2026-07-12 09:30 |
| 티커 | `시장:코드` — 시장 접두어 필수 | `KRX:005930`, `NASDAQ:NVDA` |
| 통화 | ISO 코드 | KRW, USD |
| 금액 | 통화 + 단위 명기, 재무제표는 연결/별도 구분 | 1,200억 KRW (연결) |
| 일지 파일명 | `YYYY-MM-DD_종목명_매수\|매도.md` (같은 날 같은 종목·방향이 계좌만 다르면 `_계좌별칭` 접미) | `2026-07-12_삼성전자_매수.md` |
| 종목 리포트 | `30_종목/<종목명>/YYYY-MM-DD_<주제>.md` | `30_종목/삼성전자/2026-07-15_분기실적.md` |
| 문헌 ID | 책약칭-장 2자리 | `MARGIN-03` (『Margin of Safety』 3장) |
| 발췌 파일명 | `<문헌ID>_<제목요약>.md` | `MARGIN-03_안전마진.md` |

책약칭은 읽는 문헌별로 정해 `수독인덱스.md`(독서 진도판)에 등록한다.

## 2. YAML frontmatter 스키마

### 매매일지 (`20_매매일지/일지/`)

```yaml
type: 일지
date: 2026-07-12          # 거래일
account_alias: 증권사A-ISA-0000 # 계좌 별칭 (원계좌번호 기록 금지)
market: KRX
ticker: "KRX:005930"
name: 삼성전자
side: 매수                 # 매수 | 매도
qty: 100
price: 70000
fees: 0                   # 수수료+세금
currency: KRW
data_asof: 2026-07-12 09:30   # 의사결정 당시 데이터 기준 시각
confidence: 3             # 확신도 1~5
status: 보유중             # 보유중 | 청산 | 부분청산
```

### 방법론 노트 (`10_방법론/**`)

```yaml
type: 방법론
category: 거장             # 거장 | 기법 | 거시_자산배분
status: draft             # draft | shadow | active
role: [종목선정]           # 종목선정 | 타이밍 | 리스크 | 자산배분
scope: 한국 상장주식        # 적용 대상
horizon: 중장기            # 투자기간
data_needs: []            # 필요 데이터 (예: [재무제표, 시가총액])
sources: []               # 근거 문헌ID (예: [MARGIN-03])
```

### 독서 발췌 (`95_문헌/발췌/`)

```yaml
type: 독서발췌
book: MARGIN              # 책 약칭
chapter: MARGIN-03        # 문헌 ID
title: 안전마진
read_at: 2026-07-15       # 읽은 날
status: 발췌됨             # 발췌됨 | 추출됨 | 반영됨
```

### 데이터 리포트 (데이터 파이프라인 단계 예약)

`source, fetched_at, as_of, adjusted, unit, currency, consolidated, report_id, error`

## 3. 공개/비공개 분류표

| 자산 | 위치 | 공개 여부 |
|---|---|---|
| 데이터 어댑터·리포트 생성 코드 | 공개 엔진 repo | ✅ 공개 |
| YAML 스키마·빈 템플릿·에이전트 정의(범용) | 공개 엔진 repo | ✅ 공개 |
| 합성(가상) 예시 출력 | 공개 엔진 repo | ✅ 공개 |
| 매매일지·복기 전체 | 비공개 vault | ❌ 비공개 |
| HTS 거래내역 원본·계좌 별칭표 | 비공개 vault | ❌ 비공개 |
| 보유종목·계좌·포지션 | 비공개 vault | ❌ 비공개 |
| 실제 종목 분석·복기 결과 | 비공개 vault | ❌ 비공개 |
| 방법론 노트 내용 (문헌 기반) | 비공개 vault | ❌ 비공개 (저작권) |
| **문헌 원문·스캔·장문 발췌·추출물 전부** | 비공개 vault + 외부 | ❌ 비공개 (저작권) |
| API 키·`.env`·데이터 캐시 | 비공개 | ❌ 비공개 |

> 유출 차단은 `.gitignore`가 아니라 **repo 물리 분리**로 한다. 이 repo에는 처음부터
> 비공개 자산이 들어올 수 없다.

## 4. 원문 보관 원칙 (저작권)

- 책 원문·스캔본은 repo와 vault 어디에도 넣지 않는다. vault에는 **발췌·메모부터** 들어온다.
- 발췌는 페이지 번호를 유지해 추출본이 근거 위치를 가리킬 수 있게 한다.
- 발췌도 장문 복제가 아니라 짧은 인용 + 자기 언어 요약 위주로 쓴다.
